# 이슈 수정

$ARGUMENTS 를 고친다.

## 순서

1. **파악**: 이슈 트래커가 있으면 조회한다(`gh issue view` 등). 없으면 사용자 설명을 기준으로 한다. 재현 방법이 없으면 묻는다.
2. **재현**: 고치기 전에 문제를 실제로 재현한다. 가능하면 실패하는 테스트로 만든다. 재현이 안 되면 그 사실을 알리고 멈춘다.
3. **근본 원인**: 증상이 나는 곳이 아니라 원인이 생기는 곳을 찾는다. 같은 원인을 가진 다른 호출부도 찾는다.
4. **최소 수정**: 원인을 고치는 가장 작은 변경. 주변 스타일을 따른다.
5. **확인**: 2번의 재현이 이제 통과하는지 보고, `verify`로 나머지 검증을 돌린다.
6. **보고**: 원인, 수정 내용, 확인 방법을 3~5줄로. 커밋은 요청할 때만.

## 규칙

- 증상만 덮지 않는다. 예: 원인을 모른 채 try-catch로 감싸기, null 체크만 추가하기.
- 범위 밖 리팩터링을 끼워 넣지 않는다. 발견한 개선거리는 따로 목록으로 제안한다.
- 원인을 확정하지 못했으면 가설과 근거를 보고하고 멈춘다.
