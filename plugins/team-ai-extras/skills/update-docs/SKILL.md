# 문서 맞추기

코드가 바뀌어 문서가 틀리게 된 곳만 고친다. 문서를 새로 쓰거나 다듬는 작업이 아니다.

## 순서

1. **범위**: 인자가 있으면 그 기준, 없으면 기본 브랜치와 비교한다. `git diff --stat <기준>...HEAD`와 커밋 안 된 변경을 함께 본다.
2. **바뀐 사실 뽑기**: diff에서 문서가 언급할 만한 것만 목록으로 만든다.
   - 실행·빌드·테스트 명령, 스크립트 이름
   - 환경 변수, 설정 키, 기본값
   - API 경로, CLI 옵션, 화면 이름
   - 파일·폴더 경로, 모듈 이름
   - 지원 버전, 필요한 도구
3. **문서 찾기**: 2번의 옛 이름과 새 이름으로 README, `docs/`, CLAUDE.md, AGENTS.md, plan.md를 검색한다. 이름이 그대로여도 동작이 바뀐 것(기본값, 순서)은 설명 문장을 읽어 확인한다.
4. **고치기**: 틀린 문장만 고친다. 문서의 말투, 구조, 다른 문장은 그대로 둔다.
   - 명령을 고쳤으면 안전한 것(조회, 빌드, 테스트)은 실제로 실행해 맞는지 확인한다. 배포·삭제·데이터 변경 명령은 실행하지 않고 "실행 확인 안 함"으로 보고한다.
   - 새 기능에 대한 설명이 아예 없으면 쓰지 않고 "추가할 문서 후보"로 보고한다.
5. **CLAUDE.md·AGENTS.md**: 팀 규칙 파일이라 바로 고치지 않는다. 바꿀 줄을 보여 주고 승인을 받는다.
6. **보고**: 고친 문서와 줄, 고치지 못한 것(판단이 필요한 것, 확인 못 한 명령), 추가할 문서 후보.

## 규칙

- 코드를 문서에 맞추지 않는다. 문서가 맞고 코드가 틀린 것 같으면 고치지 말고 알린다.
- CHANGELOG의 지난 항목은 기록이므로 고치지 않는다.
- 커밋은 요청할 때만. 커밋한다면 코드 변경과 분리해 `docs:` 커밋으로.
