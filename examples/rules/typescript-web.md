## 구조
- 화면 컴포넌트는 `app/`(또는 `pages/`), 재사용 컴포넌트는 `components/`, 서버 호출은 `lib/api/`에 둔다.
- Next.js App Router면 서버 컴포넌트가 기본이고, 상호작용이 필요한 곳에만 `"use client"`를 쓴다.

## 코드 스타일
- `any`를 쓰지 않는다. 외부 입력은 `unknown`으로 받고 스키마(zod 등)로 검증한다.
- 포맷은 prettier, 린트는 eslint에 맡긴다. 수동으로 정렬하지 않는다.
- 새 타입은 기존 types 파일에, 새 유틸은 기존 utils 파일에 추가한다.

## 이 스택의 함정
- 비밀값을 클라이언트 번들에 넣지 않는다. 브라우저용 환경 변수는 `NEXT_PUBLIC_` 접두사가 붙은 것만 쓴다.
- 서버 상태를 `useEffect` + `fetch`로 직접 관리하지 않는다. 프로젝트의 데이터 패칭 방식을 따른다.

## 검증
- 타입체크와 린트를 통과한 뒤, 바뀐 화면을 실제로 띄워 동작을 확인한다.
