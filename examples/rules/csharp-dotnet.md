# C# / .NET 규칙 (예시)

## 구조
- 솔루션의 프로젝트 경계를 지킨다. 화면(WPF·WinForms·Web) 프로젝트가 데이터 접근 코드를 직접 갖지 않는다.
- 새 클래스는 같은 역할의 기존 클래스가 있는 프로젝트·폴더에 둔다. 네임스페이스는 폴더 경로와 맞춘다.

## 코드 스타일
- 프로젝트의 nullable 설정을 따른다. `!`로 경고를 끄지 않고 null을 처리한다.
- 포맷은 `dotnet format`과 `.editorconfig`에 맡긴다.
- 의존성은 생성자 주입으로 받는다. `new`로 서비스를 직접 만들지 않는다.

## 이 스택의 함정
- `async void`는 이벤트 핸들러에만 쓴다. `.Result`·`.Wait()`로 비동기를 막아 기다리지 않는다(UI 스레드 교착).
- UI 스레드에서 오래 걸리는 작업을 돌리지 않는다. UI 갱신은 Dispatcher(또는 프레임워크의 동기화 방식)로 한다.
- `IDisposable`(DB 연결, 스트림, HttpClient 응답)은 `using`으로 닫는다. `HttpClient`는 매번 새로 만들지 않는다.

## 검증
- `dotnet build`가 경고 증가 없이 통과하고, `dotnet test`가 통과해야 한다. 장비·외부 시스템에 연결하는 테스트는 실행 전에 묻는다.
